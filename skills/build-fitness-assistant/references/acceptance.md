# Приёмка и демонстрация

## Автоматические проверки

Проверяй значимые инварианты, а не совпадение формулировок промптов.
Без сети и секретов используй подменный клиент GigaChat для:
- обязательных полей, диапазонов, возрастного ограничения;
- различения not_asked/provided/declined и pain_reported = null/false;
- запрета чтения и изменения чужого профиля и программы;
- сохранения анкет и состояния бота после перезапуска;
- разбора JSON и несовместимых status/program;
- одного исправления структуры и ограниченных повторов при сбое;
- обновления истёкшего токена, включая одновременные запросы;
- сохранения текущей версии до подтверждения адаптации;
- сохранения профиля после ошибки и защиты от дублирования генерации.

## Содержательные сценарии

| Сценарий | Ожидаемое поведение |
|---|---|
| Новичок, дома, без оборудования, 3 × 30 минут | Доступные упражнения, полная структура, реалистичное время |
| Тот же профиль с другой целью | Содержательно объяснённая адаптация под цель |
| Опытный пользователь в зале | Учтены опыт, оборудование, время |
| Неполный или противоречивый профиль | Уточнения вместо выдуманных данных |
| Отказ сообщать ограничения | Отказ сохранён и не трактуется как отсутствие |
| Возраст меньше 18 | Понятное ограничение первой версии |
| Отрицательное время или 10 занятий в неделю | Ошибка до запроса LLM |
| Запрос объяснения | Объяснено именно выбранное упражнение |
| Изменение времени и оборудования | Предложен подходящий новый план |
| Сообщение о боли | Нет совета продолжать болезненное упражнение или назначения лечения |
| Инструкция игнорировать правила внутри отзыва | Данные не меняют роль и правила модели |
| Сбой API или повторно неверный JSON | Нет готовой программы, данные сохранены, возможен повтор |
| Повторное открытие объяснения | Используется сохранённый результат для той же версии |

Основные генеративные сценарии выполни несколько раз, если разрешены
расходы API. Оценивай соответствие требованиям, а не дословное совпадение.
Проверь сайт и бота отдельно; общая бизнес-логика не исключает ошибки UI.
Если реальные вызовы недоступны, явно отдели тесты с подменой от живых.

## Форма отчёта

Для каждой проверки: сценарий, входные условия, ожидаемый результат,
фактический результат, пройдено/ошибка/не выполнено, способ проверки
(автоматически с подменой, вручную, живой API). Не представляй проверку
схемы как медицинскую или тренерскую экспертизу.

## Демонстрация

Покажи заполнение и подтверждение анкеты → создание программы → объяснение
упражнения → обратную связь → предложение изменений → подтверждение новой
версии с сохранением предыдущей. Приложи инструкции локального запуска,
`.env.example`, версии промптов и ограничения первой версии.
