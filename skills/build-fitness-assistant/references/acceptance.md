# Проверка, приёмка и демонстрация

## Уровни доказательств

Разделяй четыре результата:
1. Приложение запускается, процессы доступны.
2. Автотесты с подменными API проверяют логику.
3. Настоящий GigaChat проходит программные сценарии.
4. Пользовательский сценарий проверен вручную в браузере и Telegram.

Успех Flask test client с настоящим LLM не означает ручную проверку интерфейса. Проверка схемы, каталога и времени не является профессиональной оценкой пригодности тренировки.

## Автотесты без сети

Проверяй значимые инварианты:
- диапазоны анкеты и 18+, согласие, различение отказа от ответа и отсутствия ограничений;
- серверную сессию, CSRF, запрет доступа к чужой программе;
- восстановление этапа бота, отмену и сообщения в группе;
- недоступные и неизвестные id, повтор id в одном занятии;
- соответствие числа занятий, equipment и статусов;
- время с отдыхом, переходами и запасом, включая короткое занятие;
- отсутствие автоматической прибавки при адаптации, в том числе при переносе упражнения между днями;
- сообщение о боли при адаптации И при новой генерации, старые отзывы и повторные запросы;
- единственный запрос исправления и завершение после второй ошибки без готового плана;
- обновление токена, параллельные запросы, сохранение анкеты после сбоя;
- подтверждение версии, историю, кэш объяснения и отсутствие нового вызова при повторном открытии.

Список описывает желаемую приёмку, а не утверждает, что все проверки уже реализованы. При обнаружении расхождения фиксируй его отдельно, не меняй доказательства под ожидаемый результат.

## Живые сценарии

Используй изолированные синтетические профили; не меняй реальные анкеты и не вызывай платные операции вне имеющейся авторизации.

| Сценарий | Ожидание |
|---|---|
| Начинающий, дома, без инвентаря, 3 × до 30 минут | Только доступные id, полная программа, расчёт не превышает бюджет |
| Тот же профиль повторён несколько раз | Отдельно измерены успехи, исправления, отказы и длительность |
| Время сокращено до 20 минут | Реально изменён объём, а не только подпись времени |
| Изменились оборудование/цель | Учтены текущие данные, каталог не расширяется догадками |
| Ограничения не сообщены | Отказ не превращается в «ограничений нет» |
| Каталог не позволяет учесть ограничения | Уточнение либо профессиональная оценка вместо выдуманного плана |
| Запрошено объяснение | То же упражнение, доступный инвентарь и согласованная дозировка |
| Есть боль | Нет совета продолжать через боль и назначения лечения |
| Новая версия ещё не подтверждена | Прежняя остаётся текущей |
| Повторное открытие объяснения | Сохранённый результат той же версии |

Повтори основной профиль серией, если расход разрешён; затем добавь разные цели, уровни и условия. Считай needs_clarification и requires_professional_review отдельно от технической ошибки и готового плана. Нельзя считать любой HTTP 200 успешной генерацией.

## Отчёт

Укажи дату, модель, версию промпта, число сценариев и API-вызовов, ожидаемые и фактические результаты, способ проверки. Сохраняй знаменатель: 5 из 5 проверок — не гарантия для всех пользователей.

Для этого репозитория ориентиры:
- python -m unittest discover -v — локальные тесты;
- python stability_acceptance.py — серия реальных созданий и адаптаций, расходует токены;
- reports/STABILITY-REPORT.md и reports/stability-summary.json — предыдущие доказательства.

Файлы и прежние числа могут отсутствовать в другом проекте. Не копируй исторические «28 тестов» или «5/5» как новый результат; прочитай артефакты, проверь их актуальность и запусти только необходимые проверки.

Сохраняй сырой вывод только для явно синтетических анкет и отдельно от рабочих данных; объёмные результаты можно оставить локально. В общедоступный отчёт не включай реальные анкеты и секреты.

## Демонстрация для сдачи

Покажи анкету и её подтверждение → программу → объяснение упражнения → отзыв → предложение адаптации → подтверждение → предыдущую версию в истории. Пройди оба интерфейса, явно обозначив отсутствие общей привязки профилей.

Приложи описание проекта, архитектуру, набор промптов, исходный код, команды запуска, .env.example без секретов, отчёт и доказательства демонстрации. Не выдавай навык разработки за уже развёрнутый сервис.
