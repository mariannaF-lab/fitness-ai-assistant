# Подключение и диагностика GigaChat

## Настройки исходной реализации

```dotenv
GIGACHAT_CREDENTIALS=
GIGACHAT_MODEL=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_CA_BUNDLE=
GIGACHAT_PROXY_URL=
TELEGRAM_BOT_TOKEN=
TELEGRAM_BOT_USERNAME=
TELEGRAM_PROXY_URL=
COOKIE_SECURE=false
FITNESS_DB=data/fitness.db
```

Пустые значения — только шаблон. Секреты пользователь вводит локально; не проси отправлять ключи в чат. FITNESS_DB — путь SQLite, не SQLAlchemy URL. DATABASE_URL в текущем Store не читается.

Названия переменных отражают существующий проект. В другом клиенте сначала проверь его контракт. Не назначай фиксированный локальный прокси всем пользователям: порт и необходимость прокси зависят от машины.

Authorization key используется для получения временного Access token. Не меняй исправный исходный ключ из-за истечения 30 минут: срок относится к токену. Обновляй его по expires_at; исходный клиент понимает секунды и миллисекунды.

Отображаемое имя модели и API id различаются. В проверенном аккаунте API возвращал GigaChat-3-Ultra, тогда как строка GigaChat Ultra 3.5 приводила к No such model. Не считай это имя универсальным: получи актуальный список доступных моделей для данного аккаунта.

## Диагностика по слоям

| Наблюдение | Следующий шаг |
|---|---|
| Сайт открывается, бот молчит | Проверить отдельный процесс polling и авторизацию Telegram, наличие webhook/конкурирующего процесса |
| Ссылка Telegram скрыта | Проверить TELEGRAM_BOT_USERNAME и загрузку обновлённого .env; наличие токена само по себе ссылку не создаёт |
| Соединение не установлено | Проверить сеть и фактический прокси; не предполагать ошибку ключа |
| CERTIFICATE_VERIFY_FAILED | Проверить доверенную цепочку, системное хранилище и дополнительный CA-пакет |
| 401/403 при авторизации | Проверить исходный ключ, scope, доступ проекта и код ответа, не выводя секреты |
| No such model | Сверить GIGACHAT_MODEL со списком API id |
| 429 | Ограниченный повтор с учётом Retry-After, без бесконечного цикла |
| 200, но неверная структура | Проверка схемы/каталога и один запрос исправления; сетевые настройки здесь не причина |

Системный прокси Windows может быть определён неверно: например, клиент пытается установить HTTPS к локальному HTTP-прокси. Адрес прокси и HTTPS целевого сервиса — разные уровни. Исправляй настройку клиента, сохраняя TLS к GigaChat/Telegram, не меняя глобальные настройки машины без необходимости.

Системный SSL-контекст Python на Windows может использовать доверенные сертификаты Windows; дополнительную цепочку загружай из GIGACHAT_CA_BUNDLE. Не отключай проверку TLS и не доверяй произвольному сертификату из неофициального источника.

## Порядок подключения

1. Проверь наличие конфигурации без печати значений секретов.
2. Получи токен и список моделей.
3. Выполни минимальный запрос только в пределах разрешённых расходов.
4. Проверь реальную генерацию на синтетическом профиле.
5. После изменения .env или кода перезапусти соответствующие процессы; обновление страницы не перечитывает окружение Python.

В исходном репозитории check_gigachat.py проверяет авторизацию/модели, а --chat добавляет минимальную генерацию. check_telegram.py проверяет Telegram без отправки сообщений. Названия файлов — подсказка для этого репозитория, не зависимость установленного навыка: в пустом проекте создай эквивалентные проверки.

## Адаптер и секреты

Синхронизируй обновление токена для одновременных запросов. После первого 401 допускается обновление и повтор; постоянный отказ завершает операцию. Ограничивай повторы 429 и общий бюджет ожидания; не повторяй автоматически неизвестный исход генерации после сетевого тайм-аута.

Логи не содержат заголовков авторизации, URL с Telegram-токеном, ключей или медицинских ответов. Сохраняй только безопасные метрики и версии. Исключи .env, базу, журналы и реальные тестовые данные из Git до публикации.

При изменении API сверяй контракт с первичными источниками:
- https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api
- https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token
- https://developers.sber.ru/docs/ru/gigachat/guides/using-sdks

Не делай действующие тарифы и доступность модели неизменным требованием навыка. Для точных условий проверяй официальную документацию на момент подключения.
