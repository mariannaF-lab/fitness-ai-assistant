# Архитектура и данные

## Общая логика

Сайт / Telegram → общий сервис → проверка анкеты и SQLite → LLM выбирает id → сервер собирает план → проверка → сохранение → интерфейс.

Сохраняй текущую архитектуру. Для исходного проекта это Flask и python-telegram-bot, а не раннее предложение FastAPI и aiogram. MCP не нужен, если внешним ИИ-приложениям не требуется вызывать функции сервиса.

## Профиль

Подтверждённый профиль содержит:

| Поле | Контракт исходной версии |
|---|---|
| age | Целое, 18–120 |
| goal | Основная цель, текст |
| fitness_level | beginner / intermediate / advanced |
| current_activity | Текущая активность со слов пользователя |
| sessions_per_week | Целое, 1–7 |
| session_duration_minutes | Целое, 10–180, верхний предел времени |
| training_location | home / gym / outdoor |
| equipment | Список; пустой означает отсутствие инвентаря |
| health_info_status | provided / declined |
| limitations | Явный ответ или null при отказе |
| preferences | Необязательный текст |
| data_consent | true для сохранения подтверждённого профиля и отправки модели |

Неопрошенное состояние существует в черновике анкеты; не сохраняй его как подтверждённый Profile. «Ограничений нет» — provided с явным ответом; declined — отказ, а не подтверждение здоровья.

Идентификатор и канал храни отдельно от полезной нагрузки LLM. В исходной SQLite-базе владелец задаётся ключом owner: серверная веб-сессия либо Telegram ID из доверенного update. Не принимай произвольный user_id браузера как разрешение доступа. Вес, рост, ФИО и контакты не обязательны.

## Программы и объяснения

Храни id, owner, version, created, status (draft/current/archived), полный результат, снимок профиля, model и prompt_version. Первая готовая генерация становится текущей после подтверждения анкеты; каждая следующая версия требует отдельного подтверждения, даже если запрошена как новая генерация.

Тренировка: день недели 1–7, название, приблизительная длительность, разминка с минутами, упражнения, завершение с минутами. Упражнение: название, подходы, repetitions ИЛИ seconds, отдых в секундах, оборудование, техника.

В существующей схеме repetitions — строка «8» или «8-12»; seconds — целое. Не меняй совместимый формат на min/max без отдельной миграции. Объяснение привязано к владельцу, версии программы и позиции упражнения. В исходном коде используются program_id, workout_index и exercise_index; отдельные workout_id/exercise_id не реализованы. При новом проекте можно выбрать стабильные id, сохраняя проверку принадлежности и версию.

Повторное открытие объяснения той же версии использует сохранённый результат. Старое объяснение не должно автоматически прикрепляться к изменённому упражнению.

## Обратная связь

Контракт: program_id, workout_index, completion_status (completed/partial/skipped), actual_duration_minutes, perceived_difficulty (1–10 или null), pain_reported (true/false/null), comment. Владелец и дата сохраняются сервером.

Для выполненного/частичного занятия обязательны время и сложность; для пропуска не требуй их. Неизвестный ответ о боли сохраняй как null. Проверяй принадлежность программы и индекс занятия. Не считай пропуск доказательством чрезмерной нагрузки без выяснения причины.

## Сценарии и доступ

Сайт: три шага ввода → сводка → подтверждение → запрос программы. Возврат и ошибка отправки не очищают форму. Cookie-сессия изолирует профиль; изменяющие запросы требуют CSRF. Без регистрации очистка cookie может лишить доступа к прежнему профилю — обозначь это в инструкции, не обещай восстановление.

Бот работает в личном чате отдельным процессом polling. Команды исходной реализации: /start, /help, /profile, /resume, /cancel, /generate, /program, /feedback, /adapt, /history, /explain, /confirm. /profile начинает ввод заново; /resume продолжает сохранённый черновик. Не обещай, что /profile уже показывает профиль: в этой версии это ввод анкеты.

Сохраняй этап диалога в базе, давай отмену и исправление анкеты. Длинные ответы разбивай с учётом ограничений Telegram. Токен и Telegram ID не передаются GigaChat для создания плана.

Сайт и бот имеют отдельные профили, пока явно не реализована привязка. Отзыв не повышает нагрузку автоматически. Блокировку назначения новой нагрузки при боли проверяй отдельно от ответов модели.
