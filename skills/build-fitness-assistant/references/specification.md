# Архитектура и данные

## Компоненты

Сайт и Telegram-бот → общий сервис приложения → валидация и SQLite → адаптер GigaChat → проверка ответа → сохранение и отображение.

Раздели транспортные обработчики и бизнес-логику. Не вызывай LLM напрямую из браузера. Бот может вызывать общий Python-сервис либо внутренний API: выбирай по устройству проекта. Не вводи публичный endpoint доступа к профилю только по переданному user_id.

На сайте используй серверную сессию или другой проверяемый механизм доступа; в боте идентичность определяется Telegram update. Каждый запрос профиля, программы, упражнения или обратной связи проверяет принадлежность пользователю. Для изменяющих запросов сайта обеспечь подходящую защиту сессии, включая CSRF при cookie-аутентификации.

## UserProfile

| Поле | Смысл |
|---|---|
| user_id | Внутренний идентификатор, создаётся сервером |
| channel | web или telegram |
| age | Целое число; создание программы только для 18+ |
| goal | Основная цель |
| fitness_level | beginner, intermediate, advanced |
| current_activity | Активность со слов пользователя |
| sessions_per_week | Целое от 1 до 7 |
| session_duration_minutes | Положительная длительность; для MVP предложенный диапазон 10–180 минут, сообщай его в интерфейсе |
| training_location | home, gym, outdoor |
| equipment | Список оборудования; пустой список означает занятия без оборудования |
| health_info_status | not_asked, provided, declined |
| limitations | Сообщённые ограничения; null при отказе или отсутствии ответа |
| preferences | Необязательные пожелания |

Ответ «ограничений нет» хранится как provided с явным текстом. not_asked требует вопроса, declined допускает продолжение с пояснением ограничений персонализации. Не требуй вес, рост, ФИО и контакты.

## TrainingProgram

Храни program_id, user_id, version, created_at, profile_snapshot, model, prompt_version, статус draft/current/archived, schedule и workouts. Снимок профиля позволяет понять контекст старой программы. Первая подтверждённая генерация становится текущей; адаптация сохраняется как draft и становится текущей после подтверждения.

Тренировка: workout_id, название, задача, длительность, разминка, основная часть и завершение. Упражнение: exercise_id, название, подходы, повторения ИЛИ длительность, отдых, оборудование, ключевая подсказка. Используй явные единицы: секунды, минуты; не кодируй длительность в поле повторений. Диапазон повторений представь отдельными min/max, если он используется.

## WorkoutFeedback

Храни feedback_id, user_id, program_id, workout_id, completed_at, completion_status (completed/partial/skipped), actual_duration_minutes, perceived_difficulty (1–10 либо null), pain_reported (true/false/null), comment. Для пропуска не требуй длительность и оценку сложности. Проверяй принадлежность тренировки выбранной программе и пользователя.

Объяснения привязывай к версии программы и exercise_id. Повторное открытие использует сохранённое объяснение. При изменении упражнения не переноси старое объяснение автоматически.

## Сценарии

Сайт: вводный блок → анкета из трёх шагов → сводка с редактированием → подтверждение → программа. Шаги: сведения о пользователе; условия тренировок; ограничения и пожелания. Возврат и ошибка сети не очищают введённые данные. Показывай состояния ожидания, успеха и ошибки; блокируй случайные повторные отправки.

Бот: /start, /profile, /program, /feedback, /help. Используй кнопки для категорий, текст для уточнений. Состояние анкеты и введённые данные сохраняй между перезапусками процесса. Дай возможность отменить ввод или исправить профиль. Учитывай ограничения Telegram на размер сообщений, разбивай программу на логические части.

Изменение профиля не переписывает историю. Обратная связь не повышает нагрузку автоматически. При запросе адаптации выясни причину сложностей или пропуска, предложи изменения, сохрани новую версию после подтверждения. Если невозможно оценить нагрузку по сообщённым обстоятельствам, не генерируй её как готовый план.
