# Создание ИИ-гида по фитнес-программам

Разрабатывай работающего ассистента, который собирает анкету, создаёт недельный план, объясняет упражнения и адаптирует программу по обратной связи. Общайся с пользователем по-русски и объясняй решения так, чтобы их можно было представить на защите учебного проекта.

## Согласованная основа

- Аудитория первой версии — взрослые от 18 лет.
- Интерфейсы — сайт с пошаговой анкетой и Telegram-бот. Отдельный маркетинговый лендинг не требуется: достаточно вводного блока над анкетой.
- Предпочтительный стек — Python, FastAPI, aiogram и SQLite; учитывай уже существующий код и явные изменения требований.
- Поставщик LLM — GigaChat API. Конкретную доступную модель определяй по аккаунту и тестовому запросу, не считай рекламный пример подтверждением доступа.
- Анкету собирает приложение без LLM. Модель создаёт программу, объясняет упражнения и предлагает адаптацию.
- Сайт и бот используют общие схемы, промпты и сервисы. Их профили раздельны до явного связывания аккаунтов; не объединяй их по имени.
- Не включай питание, реабилитацию, оплату и интеграции с браслетами без отдельного запроса.

Эти решения уже согласованы для исходного проекта. Не запрашивай их подтверждение заново. Если пользователь хочет сначала согласовать следующий этап, подготовь его проект и дождись ответа до зависимой реализации. Сам вызов навыка не разрешает публикацию, создание внешних ресурсов или платные операции.

## Порядок работы

1. Прочитай инструкции репозитория, осмотри существующие файлы и определи текущий этап. Сохраняй пользовательские изменения.
2. Для проектирования и серверных моделей прочитай [references/specification.md](references/specification.md).
3. Реализуй вертикальный сценарий: анкета → проверка → подтверждение → сохранение → запрос LLM → проверка → отображение. Подключай оба интерфейса к общей логике.
4. Для LLM прочитай [references/prompts.md](references/prompts.md) и [references/gigachat.md](references/gigachat.md). Проверяй актуальные API-контракты по официальной документации перед подключением.
5. Добавь объяснение упражнения, обратную связь и подтверждаемую адаптацию с историей версий.
6. Проверь результат по [references/acceptance.md](references/acceptance.md). Отличай реальные проверки от заглушек и невыполненных сценариев.
7. Передай пользователю инструкции запуска, настройку секретов, результаты проверок и известные ограничения. При публикации навыка проверь структуру и возможность установки через skill-installer.

## Обязательные свойства результата

- Сервер независимо валидирует данные обоих интерфейсов. Пропущенный ответ об ограничениях не означает их отсутствие.
- Ответ модели — типизированная структура со статусом, а не произвольный Markdown. Непрошедший проверку результат не становится готовой программой.
- Изменения нагрузки предлагаются по запросу пользователя. Новая программа становится текущей после подтверждения; старая сохраняется.
- Ключ авторизации GigaChat, Access token и токен Telegram не попадают в браузер, Git, ответы и логи. В репозитории допустим только `.env.example` с пустыми значениями.
- Медицинские сведения не копируются в технические журналы. В LLM передаётся только необходимая для задачи информация без контактных и технических идентификаторов.
- Не ставь диагнозы, не назначай лечение и не обещай результат. Сообщение о боли не должно приводить к совету продолжать болезненное упражнение.
- Не объявляй API, бота или размещение работающими без успешной фактической проверки. Если секреты ещё не настроены, сохрани пригодную к запуску реализацию и точно обозначь непроверенный участок.
