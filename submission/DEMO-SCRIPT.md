# Сценарий защиты «Ритм» — 5–7 минут

Это план выступления и показа. Перед записью выполните CHECKLIST.md.
Используйте синтетическую анкету; повторы API расходуют токены.

## 0:00–0:40 — задача проекта

**На экране:** главная страница сайта «Ритм».

**Текст:**

> Мой учебный проект — ИИ-гид по фитнес-программам «Ритм». Он помогает
> взрослому пользователю подобрать недельный план по цели, опыту, времени
> и оборудованию, объясняет упражнения и предлагает изменения по отзыву.
> Есть сайт и Telegram-бот с общей логикой. Рекомендации информационные.

## 0:40–1:40 — анкета

**Действия:** откройте анкету, заполните три шага, покажите сводку,
нажмите «Подтвердить анкету».

| Поле | Учебное значение |
|---|---|
| Цель | Общая физическая форма |
| Возраст | 28 |
| Опыт | Начинаю с основ |
| Активность | Сидячая работа, ежедневные прогулки |
| Место | Дома |
| Частота | 3 раза в неделю |
| Время | До 30 минут |
| Оборудование | Пустое поле — без оборудования |
| Ограничения | «Хочу сообщить» → «Ограничений нет» |
| Пожелания | Без прыжков |
| Согласие | Подтвердить для учебного профиля |

**Текст:**

> Анкету собирает приложение, а не языковая модель. Обязательные поля
> проверяются на сервере. Отказ отвечать об ограничениях отличается
> от ответа, что ограничений нет. Перед отправкой можно проверить данные.

## 1:40–2:30 — создание программы

**Действия:** нажмите «Создать программу», дождитесь результата.
Покажите три занятия, разминку, подходы, повторения/время, отдых и завершение.

**Текст:**

> GigaChat выбирает упражнения из каталога, доступного для этой анкеты.
> Сервер собирает полный план и рассчитывает время вместе с отдыхом.
> Модель не может добавить неизвестный id или скрытый инвентарь в готовый план.
> Указанные 30 минут — верхняя граница: начальная программа может быть короче.

Число минут и выбранные упражнения при живом запросе могут отличаться
от сохранённого DEMO-EXAMPLE.md. Показывайте фактический результат.

## 2:30–3:00 — объяснение упражнения

**Действия:** нажмите «Как выполнять» возле упражнения. Покажите исходное
положение, шаги, дыхание, ошибки и условия прекращения. Закройте окно.

**Текст:**

> Это отдельный запрос к модели по выбранному упражнению. Объяснение
> проверяется и сохраняется для данной версии программы. Повторное открытие
> использует сохранённый результат и не требует нового запроса.

## 3:00–4:20 — отзыв и адаптация

**Действия:** нажмите «Оставить отзыв о занятии» и введите:

- выполнение — частично;
- фактическое время — 16 минут для учебного примера;
- сложность — 7 из 10;
- боль — нет;
- комментарий — «Учебный пример: занятие оказалось сложным, могу выделять до 20 минут».

Сохраните отзыв. В анкете измените время на 20 минут и снова подтвердите её.
В разделе адаптации введите:

> Могу выделить до 20 минут вместо 30. Прошлое занятие оказалось сложным,
> оценка 7 из 10. Предложите меньшую нагрузку, без прыжков.

Нажмите «Предложить изменения». Покажите текущую и предложенную версии.
Нажмите «Принять эту версию» и покажите сохранённую предыдущую.

**Текст:**

> Отзыв не меняет программу автоматически. Здесь учитывается и новое время,
> и высокая субъективная сложность. Сначала создаётся предложение; текущая
> программа меняется после подтверждения, предыдущая сохраняется в истории.

Если первая программа уже была короче 20 минут, не говорите, что сервер
исправил превышение времени. Покажите фактическое изменение объёма по отзыву.

## 4:20–5:20 — Telegram

**На экране:** свой чат с @ritm_fitness_bot. Нажмите «Запустить» либо /start.

**Действия:** покажите список команд и начало /profile. Если учебная анкета
в боте уже подготовлена на репетиции, используйте /program для показа плана.
При необходимости /generate создаёт новый план; для второй и следующих версий
потребуется /confirm с фактическим номером, указанным ботом.

**Текст:**

> Бот получает те же данные в диалоге. Он использует общий сервис с сайтом,
> но пока отдельный профиль: переход по ссылке не переносит анкету сайта.
> Можно объяснить упражнение, оставить отзыв и предложить адаптацию командами.

Не тратьте весь показ на повторение анкеты. Для подготовки бота используйте
список ответов из CHECKLIST.md. Не показывайте личную историю переписки.

## 5:20–6:20 — архитектура и тестирование

**На экране:** схема в PROJECT-REPORT.md, затем таблица в
reports/STABILITY-REPORT.md или stability-summary.json.

**Текст:**

> Сайт и бот обращаются к общему серверу Python. Данные и версии хранятся
> в SQLite, ответы проверяются Pydantic. GigaChat выбирает упражнения
> и объясняет технику, сервер отвечает за числовые ограничения.
> После изменения схемы прошли 28 автоматических тестов. На учебном профиле
> пять созданий и пять адаптаций прошли с первого запроса. Это проверенная
> серия, а не гарантия для всех пользователей.

## 6:20–7:00 — ограничения и развитие

**Текст:**

> Сейчас это локальный учебный прототип для взрослых. Каталог содержит
> 12 упражнений, общей привязки аккаунтов и публичного хостинга нет.
> Следующие задачи — расширение каталога, дополнительные сценарии разных
> целей и ограничений, проверка всех путей работы с отзывами и размещение.

## Если на показе нет сети

Откройте DEMO-EXAMPLE.md и evidence.json. Скажите:

> Сейчас показываю сохранённый результат реального теста от 19 октября,
> а не новый запрос к модели. Здесь видны исходная программа, объяснение
> и адаптация; запуск живого API требует подключения к сети.

## Короткий вариант на 3 минуты

Покажите подтверждённую анкету → программу → объяснение → предложенную новую
версию и историю → /start в боте → результаты тестов. Прочитайте вступление,
одну фразу о разделении LLM/сервера и ограничения. Повторное заполнение анкеты
и команды запуска оставьте в приложенных материалах.
