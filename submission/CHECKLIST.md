# Перед демонстрацией

## Подготовка компьютера

- Откройте папку проекта и два терминала. Если процессы уже работают, не запускайте вторые экземпляры.
- При необходимости запустите `python app.py` и отдельно `python bot.py`.
- Откройте http://127.0.0.1:8000/ и Telegram-бота https://t.me/ritm_fitness_bot.
- Убедитесь, что работает локальный прокси, если он указан в настройках.
- Ключи уже настроены в локальном .env; для повторного показа их менять не нужно.
- Оставьте .env закрытым на время записи. Используйте учебную анкету, отдельный профиль браузера или тестовую сессию.
- Откройте DEMO-SCRIPT.md, DEMO-EXAMPLE.md и отчёт устойчивости как материалы выступления.
- Проверьте, куда сохраняется видеозапись, звук микрофона и читаемость текста на экране. Само видео в пакет не включено.

Сайт и бот — отдельные процессы. Сайт может открываться, когда бот остановлен;
кнопка Telegram не подтверждает, что polling работает.

## Репетиция бота

В своём учебном чате отправьте /profile. Эта команда начинает ввод заново;
для незаконченной анкеты есть /resume.

Ответы по порядку:

```text
28
Общая физическая форма
Начинающий
Сидячая работа, ежедневные прогулки
3
30
Дома
Без оборудования
Сообщить
Ограничений нет
Без прыжков
Согласен
Подтвердить анкету
```

Затем /generate. Дождитесь результата. /program показывает текущую программу,
/history — версии. Если новая программа предложена поверх существующей,
примите именно её номер командой `/confirm НОМЕР` из сообщения бота.

Для объяснения скопируйте команду /explain из нужного упражнения:
номер программы и позиции должны соответствовать фактическому результату.
Не используйте заранее заготовленный номер 1 для произвольной версии.

## Признаки готовности

| Проверка | Что должно быть видно |
|---|---|
| Сайт | Страница открывается и анкета сохраняется |
| GigaChat | Готовая программа после реального запроса либо понятное сообщение об ошибке |
| Бот | На /start приходит список действий |
| Объяснение | Инструкция относится к выбранному упражнению |
| Адаптация | Есть предложение, подтверждение и предыдущая версия |
| Доказательства | В отчёте показаны дата и реальные результаты, не только план тестов |

## Если возникла ошибка

- После изменения .env перезапустите нужный Python-процесс.
- Если бот молчит, проверьте его терминал и сеть; не запускайте два polling-процесса на одном токене.
- Для отдельной проверки: `python check_telegram.py` и `python check_gigachat.py`.
- Существующий Authorization key не меняют из-за истечения Access token: временный токен обновляет приложение.
- При отсутствии сети покажите сохранённый пример, явно назвав его записью результатов API-теста.

## Что передать преподавателю

- ZIP с исходниками и материалами.
- PROJECT-REPORT.md и PROMPTS.md.
- Запись экрана по DEMO-SCRIPT.md либо живой показ.
- Отчёт устойчивости и evidence.json как подтверждение серии тестов.

Сайт локальный; для самостоятельной проверки преподаватель запускает его
по SETUP.md со своими настройками доступа. Ключи и пользовательская база
в архив сдачи не включаются.

## Возможные вопросы

**Где здесь LLM, если сервер считает подходы?**

Модель выбирает упражнения по данным пользователя, оценивает контекст запроса
и создаёт объяснения. Сервер обеспечивает формат, время, дозировку и хранение.

**Почему не оставить всю генерацию модели?**

Большой JSON оказался нестабильным. Компактный выбор id сократил ошибки,
а расчёт времени стал воспроизводимым и проверяемым обычными тестами.

**Как обеспечивается персонализация?**

Профиль влияет на доступные упражнения, выбор модели, частоту, начальную
дозировку и доступное время. Отзыв используется при следующем предложении.
Разнообразие ограничено текущим каталогом; не утверждаем медицинскую точность.

**Почему после лимита 30 минут тренировка короче?**

Лимит означает доступное время, а не обязательный объём. Начальный план
может быть короче, с запасом для отдыха и индивидуального темпа.

**Что именно проверено?**

28 автотестов и пять повторов одного полного сценария с реальным GigaChat.
Это не эквивалент проверки всех целей, медицинских ограничений и интерфейсов.

**Есть ли общая анкета сайта и Telegram?**

Общая бизнес-логика есть; автоматической привязки профилей пока нет.

**Нужны LangChain, n8n или MCP?**

По заданию можно выбрать Python. В данном проекте прямого API и общего
Python-сервиса достаточно; дополнительные слои не обязательны.
